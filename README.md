# BlackTec Mafia — нуарная «Мафия» в браузере

Настольная социальная игра в браузере: 6–12 игроков за столом, нуарная доска 1940-х,
соло против ботов и онлайн-комнаты по ссылке. Ничего устанавливать не нужно.

**Живая сборка для теста:** https://blacktecmafia.github.io/blacktec-mafia/

```bash
npm install
npm run dev          # http://localhost:5173/
```

Для сетевого режима с каталогом комнат дополнительно запустите сервис обнаружения:

```bash
npm run discovery    # http://127.0.0.1:8787 — список открытых комнат
```

Адрес сервиса задаётся переменной `VITE_DISCOVERY_URL` (см. `.env.local`) либо прямо
в поле «Сервис подбора комнат» на экране «Найти игру» — он сохраняется в браузере.

## Как тестировать и сообщать о багах

1. Откройте https://blacktecmafia.github.io/blacktec-mafia/ (лучше в отдельном профиле
   браузера, чтобы не мешать своей сессии).
2. Проверьте соло-режим: «Сесть за стол» → 8 игроков → ночь, рассвет, обсуждение,
   голосование, финал.
3. Проверьте онлайн: один браузер — «Создать комнату», второй — открыть ссылку-приглашение
   или ввести код комнаты. Для проверки защиты — «Пользовательская комната» с паролем.
4. Проверьте голос: во время обсуждения — «Включить микрофон» (понадобится разрешение
   браузера на доступ к микрофону).
5. Ошибки и странности — в **Issues**: https://github.com/BlackTecCom2000/blacktec-mafia/issues

В issue удобно писать: что делали, что ожидали, что получили, браузер и ОС, скриншот или
видео. Отдельно отметьте, если проблема только в онлайне (тогда нужны код комнаты и
время, когда она была открыта).

## Что умеет

| Режим | Описание |
| --- | --- |
| **Соло** | Один человек, остальные места занимают боты. Партия начинается сразу. |
| **Стандартная комната** | Хост создаёт комнату, гости заходят по коду из пяти символов или по ссылке `#/join/КОД`. |
| **Пользовательская комната** | Свой состав ролей, свои тайминги, пароль, лимит мест, ручное управление фазами. |
| **Найти игру** | Каталог открытых комнат и быстрый подбор. |
| **Голосовой чат** | Микрофон во время обсуждения: хост ретранслирует потоки, мёртвые говорят только с мёртвыми. |

Интерфейс полностью на русском и английском (переключатель RU/EN в шапке).

## Правила

### Роли

| Роль | Сторона | Ночное действие |
| --- | --- | --- |
| Мафия | Мафия | Выбирает жертву. Каждый мафиози голосует сам, итоговая цель — большинство голосов; при ничьей этой ночью никто не погибает. |
| Доктор | Город | Спасает одного игрока (может спасти себя). Каждый доктор спасает своего. |
| Детектив | Город | Проверяет одного игрока: мафия он или нет. |
| Шериф | Город | Проверяет одного игрока и узнаёт, входит ли тот во враждебную фракцию — мафию **или** маньяка. |
| Маньяк | Одиночка | Убивает одного игрока. Каждый маньяк выбирает цель отдельно. |
| Горожанин | Город | Ночного действия нет. |

Одна и та же роль может встречаться несколько раз: 6 маньяков, 1 шериф и 2 жителя — валидный состав (см. «Пользовательская комната»).

### Условия победы

Правила одинаковы в движке, в интерфейсе и в журнале партии:

* **Город** побеждает, когда в живых не осталось ни мафии, ни маньяка.
* **Мафия** побеждает, когда мафии не меньше, чем горожан (маньяк не считается ни городом, ни мафией).
* **Маньяк** побеждает, когда остаётся **единственным** живым игроком. При двух выживших маньяк не побеждает — игра продолжается.
  В пользовательской комнате это правило можно переключить на «все живые — маньяки»: тогда побеждает вся фракция маньяков.

### Голосование

* Подсчитываются только поданные голоса; воздержавшиеся считаются отдельно и не работают в пользу кандидата.
* Изгоняется кандидат, у которого **больше голосов, чем у любого другого кандидата, и больше, чем воздержавшихся**.
* При равенстве голосов — ничья, никто не изгоняется.
* Мёртвые не голосуют и не пишут в общий чат: они только наблюдают.

### Фазы и таймеры

Ночь → рассвет → обсуждение → голосование → приговор → ночь. Длительности задаёт хост
(в стандартной комнате — 24 / 60 / 35 / 6 секунд, в пользовательской — свои).
Хост **не может** пропускать фазы, пока выключен переключатель «Ручное управление фазами»;
когда он включён, в панели фазы появляется кнопка «Дальше», а в шапке — метка «ручные фазы».

### Ночные решения

Выбор ночного действия фиксируется явно: сначала игрок выбирает цель на столе, затем
нажимает «Подтвердить выбор». Когда все роли сделали выбор, ночь фиксируется, но
остаётся короткое окно (3 секунды), в котором решение ещё можно изменить — об этом
сообщается в панели фазы.

### Готовность в лобби

Каждый игрок подтверждает готовность кнопкой «Готов», рядом с именем виден статус,
сверху — счётчик «5 из 8 готовы». Боты считаются готовыми автоматически (это видно по
метке «бот · готов»). Партию запускает **хост отдельной кнопкой**, и только когда все
подтвердили готовность, а число игроков совпадает с числом ролей. Любое изменение
настроек, состава или списка игроков сбрасывает готовность.

## Пользовательская комната

Отдельный режим создания (кнопка «Пользовательская комната» в меню), не смешанный со
стандартной комнатой. Хост задаёт:

* название комнаты;
* пароль (включается переключателем);
* максимальное число мест (технический максимум — 24, искусственного лимита в 12 нет);
* вход по ссылке — вкл./выкл.;
* заполнение свободных мест ботами — вкл./выкл.;
* длительности ночи, обсуждения, голосования и показа результатов;
* ручное управление фазами — вкл./выкл.;
* правило победы маньяка: «остался последним» или «все живые — маньяки»;
* голосовой чат — вкл./выкл.;
* набор ролей: стандартный (6–12) или пользовательский.

### Редактор состава

В пользовательской комнате хост сам задаёт количество каждой роли: кнопки «−»/«+» и
поле ввода, любую роль можно добавить в нескольких экземплярах (в том числе мафию,
маньяка, доктора, шерифа и жителя). Под списком показываются общее число ролей и число
занятых мест; если числа не совпадают, игра не запустится (режим неполного состава
можно включить отдельным переключателем). Есть кнопка возврата к стандартным ролям.
Отрицательные значения, переполнение и составы без города запрещены. Состав хранится
в комнате, передаётся всем участникам и не может быть изменён после старта партии.

### Пароль

* Гость запрашивает пароль у хоста: без него в лобби не пускают.
* Неверный пароль даёт понятную ошибку и не открывает доступ.
* Пароль проверяет **хост**, он не передаётся другим участникам, не показывается в
  интерфейсе и не попадает в журнал. В состоянии комнаты хранится только признак
  «пароль установлен».
* Хост может сменить или снять пароль прямо в лобби.
* На соединение даётся не больше 5 попыток входа — защита от перебора.

## Найти игру и быстрый подбор

Экран «Найти игру» показывает каталог открытых комнат: название и код, число игроков и
максимум мест, стандартные или пользовательские правила, признак «с паролем» и статус
(«Набор игроков», «Все готовы», «Игра идёт», «Комната заполнена»). Кнопка входа
активна только пока комната набирает игроков и есть свободные места.

Быстрый подбор ищет комнату, которая: без пароля, ещё не началась, принимает игроков и
совместима с выбранным режимом (стандартные / пользовательские правила) и с выбранным
числом игроков. Комнаты с паролем в подбор не попадают никогда. Если подходящей комнаты
нет — предлагается создать новую открытую комнату или обновить список.

**Важно:** PeerJS не умеет перечислять комнаты (каждая комната — анонимный peer id), поэтому
каталог и подбор работают через отдельный сервис обнаружения — `server/discovery.mjs`.
Он принимает только публичные метаданные (код, название, число игроков, максимум мест,
признак пароля, тип правил, статус) и никогда не получает пароли и имена игроков.
Без запущенного сервиса экран честно сообщает, что список недоступен — данные не
имитируются.

В каталоге лежат **только живые комнаты**:

* хост публикует комнату и обновляет запись раз в 5 секунд;
* при выходе из комнаты или закрытии вкладки хост отправляет `POST /api/rooms/<код>/close`
  — запись исчезает мгновенно;
* если хост упал и не успел закрыться, запись устаревает через 30 секунд и удаляется
  автоматически;
* комната, в которую не удалось войти, убирается из списка сразу.

```bash
npm run discovery        # порт 8787, переменные PORT и HOST
```

### Каталог комнат в интернете

Сервис каталога должен быть доступен из интернета — GitHub Pages статику не исполняет.
Быстрый способ: публичный туннель Cloudflare (аккаунт не нужен):

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start-catalog.ps1
```

Скрипт поднимает сервис на `127.0.0.1:8787` и печатает публичный адрес. Его нужно
вписать в поле «Сервис подбора комнат» на экране «Найти игру» (адрес сохраняется в
браузере) или пересобрать сайт с `VITE_DISCOVERY_URL=<адрес>`. Публичный адрес меняется
при каждом перезапуске туннеля.

Для постоянного адреса сервис стоит поднять на своём хостинге с Node.js
(Render, Railway, Fly.io) — тогда `VITE_DISCOVERY_URL` указывает на него и пересборка
не нужна.

## Голосование за исключение

В лобби и во время партии можно отправить предложение исключить участника. Голосование
открывает любой игрок (хост не имеет скрытого иммунитета), одновременно может идти
только одно голосование, между голосованиями действует пауза 45 секунд.

* Голосуют «За» и «Против», инициатор не получает дополнительного голоса, молчание
  голосом «За» не считается.
* Для прохождения нужно не меньше половины голосующих (минимум 2) и больше голосов
  «За», чем «Против».
* Показаны таймер, текущие счётчики и требуемый порог.
* В лобби успешное голосование освобождает место. Во время партии состав не меняется:
  участник отключается от комнаты, а его персонаж переходит под управление бота.
* Все решения считает авторитетная сторона (хост), интерфейс не может их подделать.
* В журнале пишется только факт голосования, без лишних данных.

## Голосовой чат

* Микрофон выключен по умолчанию и включается только по явному нажатию «Включить микрофон».
* Есть кнопки «Отключить микрофон» и «Отключить звук», состояние и говорящие участники
  видны в панели голоса.
* Доступ разрешён только в фазе обсуждения; ночью — только мафии (если это разрешено
  правилами комнаты). В остальные фазы микрофон закрыт.
* Мёртвые говорят только с мёртвыми: хост держит «живую» и «наблюдательскую» стороны
  раздельно.
* Голос передаётся участникам комнаты и **не записывается, не сохраняется и не
  транскрибируется**. В интерфейсе есть соответствующее предупреждение.
* При уходе, отключении и повторном подключении потоки и peer-соединения очищаются.

Транспорт: WebRTC (offer/answer/ICE) поверх уже существующего канала данных PeerJS,
хост выступает сигнальным узлом и ретранслятором. Внешние сервисы не требуются, кроме
публичных STUN-серверов Google (`.env`/код `ICE_SERVERS`).

## Что нужно на сервере для полноценной работы в интернете

1. **Сервис обнаружения комнат** (уже в комплекте, `server/discovery.mjs`) — HTTP API
   `GET /api/rooms`, `POST /api/rooms`, `DELETE /api/rooms/:code`. Нужен публичный
   адрес, чтобы список видели все; его следует вынести за HTTPS-прокси.
2. **Сигнальный сервер PeerJS** — сейчас используется публичный `0.peerjs.com`. Для
   своей игры поднимите `peerjs-server` и передайте адрес в `src/net/peer.ts`
   (`new Peer(id, { host, port, path, secure })`). Свой сервер снимает лимиты
   публичного брокера и его зависимость от доступности.
3. **TURN-сервер** — для сетей, где прямой WebRTC-канал заблокирован: coturn с
   учётными данными в `ICE_SERVERS` (`src/net/voice.ts`). Без него голос и PeerJS-канал
   не поднимутся у части пользователей.
4. **HTTPS** — обязателен вне `localhost`: браузер даёт доступ к микрофону только в
   защищённом контексте.
5. Хост держит комнату в своём браузере: если вкладка хоста закрылась, комната исчезает.

## Архитектура

```
src/
  game/        домен: types, roles, engine (правила и фазы), bots, view (фильтрация)
  net/         peer (PeerJS-протокол), code (коды и ссылки), rooms (каталог и подбор),
               discovery (клиент сервиса), voice + voice-rules (WebRTC и правила доступа)
  components/  интерфейс: меню, настройка комнаты, «найти игру», лобби, стол, чат
  session.ts   оркестратор: соло / хост / гость, игровой цикл, рассылка снапшотов
  i18n.tsx     русские строки (+ i18n.en.ts подгружается по требованию)
server/
  discovery.mjs  сервис каталога комнат (без зависимостей)
tests/         engine.test.ts (56), rooms.test.ts (15), i18n.test.ts (7)
```

Движок — чистый TypeScript без DOM. Хост авторитетен: он держит состояние, гости
получают отфильтрованные снапшоты (чужие роли скрыты до смерти, ночные решения и
результаты проверок — приватные). Синхронизация — по версии состояния, снимок
отправляется только при изменении.

## Ограничения

* Онлайн — прямое P2P-соединение между браузерами: нужен доступ к сигнальному серверу
  PeerJS, а в закрытых сетях — TURN.
* Партия живёт, пока открыта вкладка хоста.
* На телефоне панель фазы переносится под стол (иначе она накрывала бы места), поэтому
  игровой экран прокручивается.
